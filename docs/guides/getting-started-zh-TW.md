# llm-wiki-km 快速入門

> 狀態：`CURRENT`。給第一次使用 llm-wiki-km 的人；約 5–10 分鐘可完成第一個工作區、上傳文件、開始提問，並理解如何把好答案保存成持久知識。
>
> 本指南是學習輔助，不是 API 或資料庫契約。可複製的 endpoint、狀態值和設定鍵仍以目前程式碼與測試為準。

## 1. 先理解它是什麼

llm-wiki-km 是**以本機為優先的個人知識庫**。你先建立工作區，再從「文件」上傳內容；系統會自動抽取與建立搜尋索引，準備好後直接告訴你「可以開始使用」。

接著你可以從「知識」閱讀已發布內容，或到「提問」取得有引用來源的回答。若某個回答值得長期保存，按「保存成知識」，再到「待我審核」核准、預覽並由你明確發布。

提問的回答是暫時結果，不會自行修改持久知識。任何要進入已發布知識的內容，都必須經過人工治理流程。

## 2. 五個核心入口

| 入口 | 你可以把它想成 | 主要用途 |
| --- | --- | --- |
| 開始 | 建立或切換目前使用的工作區 | 選擇知識根目錄，確認系統基本狀態 |
| 文件 | 文件進入知識庫的入口 | 上傳後自動處理，直到顯示「可以開始使用」 |
| 知識 | 已發布、可閱讀的持久知識 | 閱讀已發布內容、前往提問 |
| 提問 | 對目前工作區做一次有依據的檢索與回答 | 找答案、看引用、保存值得長期保留的回答 |
| 待我審核 | 需要你做決定的知識整理工作 | 核准提案、預覽草稿、明確發布 |

「進階」區另外保留檢視器、品質與其他診斷能力。第一次使用時不需要理解這些工具，也不會因為沒有使用它們而被阻擋。

## 3. 啟動與開啟畫面

先確認已安裝 Java 21 與 Maven 3.9+，在 repository 根目錄執行：

```bash
mvn spring-boot:run
```

接著用瀏覽器開啟 <http://127.0.0.1:8765/>。預設只綁定本機；瀏覽器只呼叫本機 REST API，不直接碰 SQLite、檔案系統或服務提供者金鑰。

第一次使用時，先照主導覽的順序操作：

1. **開始**：建立或切換工作區。
2. **文件**：上傳文件，等待系統處理完成。
3. **知識**：閱讀已發布內容。
4. **提問**：取得有引用來源的回答。
5. **待我審核**：處理你主動保存的知識內容。

若「待我審核」旁顯示「2 件待審」之類的提示，表示目前有 2 件內容等你處理；點進去即可。

## 4. 5–10 分鐘的第一個流程

### 步驟一：建立工作區

到「開始」，輸入名稱與本機絕對路徑，例如 `/Users/you/knowledge-root`，建立工作區。

系統會建立可重建的 `inbox/`、`archive/`、`vault/`、`data/`、`config/`、`logs/`、`temp/` 目錄；不會刪除既有內容，也不會讓瀏覽器直接連到檔案系統。

### 步驟二：上傳文件

切到「文件」，上傳一個 PDF、Markdown 或其他支援格式。

系統會自動排入有界的文件處理工作；你不需要另外理解或手動執行抽取、FTS 或索引。

畫面可能顯示：

- 「系統正在處理」
- 「可以開始使用」
- 「搜尋索引尚未就緒」
- 「需要 OCR」
- 其他明確狀態

只有顯示「可以開始使用」時，才代表目前文件已通過可搜尋的現行性檢查。這時可以直接按「開始提問」。

整理／分類／標籤是可選操作，不會阻塞你先使用文件內容。

### 步驟三：閱讀或提問

若工作區已有已發布內容，可到「知識」閱讀。

想直接從文件找答案時，到「提問」；也可以從一份已顯示「可以開始使用」的文件按「開始提問」，讓問題限制在目前這份文件。

問題越具體，越容易得到可驗證的引用。回答下方的「引用來源」可以開啟來源定位；若內容已變動而不再符合權威狀態，系統不會把過時內容當成有效證據。

### 步驟四：把好答案保存成知識（可選）

Ask 的回答不會自動寫入知識庫。確認回答與引用後：

1. 按「保存成知識」。
2. 到「待我審核」；若有待處理項目，導覽會顯示「N 件待審」。
3. 檢查提案摘要、目標與證據。
4. 核准後，系統會自動準備草稿／預覽。
5. 核准不等於發布；最後仍要由你明確按「發布」。
6. 發布成功後按「閱讀已發布知識」，即可直接看到剛發布的內容。

這個流程刻意保留人工發布關卡，避免 AI 或背景工作自行改動持久知識。

## 5. 常見狀態怎麼看

| 畫面狀態 | 意義 | 建議動作 |
| --- | --- | --- |
| 空白／尚無資料 | 尚未建立工作區、沒有文件或沒有已發布內容 | 先建立工作區、上傳文件或完成待審內容 |
| 載入中／處理中 | 後端正在讀取或執行非同步作業 | 等待後重新整理，不要重複送出 |
| 可以開始使用 | 文件已完成必要處理，可開始搜尋／提問 | 直接按「開始提問」或前往「提問」 |
| 有依據的回答 | 回答有引用來源支持 | 檢查引用，決定是否保存成知識 |
| 部分完成／已降級 | 某個可選投影或項目失敗，但基礎能力仍可用 | 需要時再到進階診斷畫面檢查 |
| 錯誤／無法使用 | 請求被拒絕、服務未設定或資料不再符合權威狀態 | 依畫面提示處理；不要猜測或繞過治理流程 |

系統會把公開錯誤簡化為穩定的錯誤代碼與安全說明；絕對路徑、SQL、token、stack trace 與服務提供者原始回應只留在伺服器端紀錄。

## 6. 資料與隱私邊界

- 工作區內容、SQLite 中繼資料與可重建投影預設留在本機。
- 瀏覽器不持有服務提供者金鑰，也不直接呼叫 LLM／embedding provider。
- Ask 或文件分析若啟用遠端服務，送出的資料範圍由後端設定與 UI 的服務提供者傳輸提示決定；啟用前請確認服務提供者、傳輸方式與資料類型。
- 遠端 HTTP（非 HTTPS）只有在明確的後端 opt-in 下才可能使用，不適合作為正式設定。
- Graph／向量等投影是可刪除、可重建的衍生資料，不是權威知識來源；SQLite 與 `vault/`／`archive/` 的治理邊界仍是準則。

## 7. 技術名稱和畫面名稱不同時怎麼看

部分底層技術名稱因相容性會保留，例如：

- `inbox/`：固定目錄與 API 概念；目前主要導覽顯示「文件」。
- `#/wiki`、Wiki domain identifier：底層技術名稱；目前主要導覽顯示「知識」。
- review API／程式碼：底層審核概念；目前主要導覽顯示「待我審核」。

操作時以畫面顯示名稱為準；除非你正在看 API、程式碼或架構文件，否則不需要先學底層名稱。
