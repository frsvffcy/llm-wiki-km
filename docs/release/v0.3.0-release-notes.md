## 自 v0.2.1 以來的主要使用變化

- **上傳後可直接使用**：Browser 上傳可 opt-in 排入有界的背景 ingest；Inbox 顯示處理與搜尋索引 readiness，只有 backend 判定 `READY_TO_USE` 才導引至 Ask。使用者可看到 pending、stale 或失敗狀態，不必靠 `parseStatus` 猜測是否可搜尋。批次部分失敗會如實顯示。
- **對單一文件提問**：從 Inbox 開始 Ask 時，查詢與 evidence 限定在所選文件；Ask 顯示目前範圍，可解除範圍回到一般 Ask。過期、已刪除、不符合資格或不屬於目前 workspace 的文件不會被當成有效 evidence。scoped lexical fallback 只使用該文件的可用詞彙；零命中與有 evidence 但回答不足會分開呈現。Ask 仍是 ephemeral，不會直接寫入知識庫。
- **整理來源與知識**：使用者可以檢視上傳後產生的分類／tag 建議，並調整可編輯 Proposal 的 Wiki tags。建議本身不會寫入 canonical knowledge；Wiki tag 是 durable authority，tag 操作不改 retrieval。
- **審核後準備草稿**：核准 Proposal 後會建立或重用一份可用 Draft，方便接續檢視 preview／diff；發布仍是另一個明確的人為動作，核准不會自動 publish。每個 workspace／proposal 同時最多一份 `DRAFT`／`READY` 草稿。
- **日常導覽與操作**：Browser 導覽分成 Basic／Advanced；常用 Workspace、Inbox、Ask、知識整理與 Review 更容易找到，Inspect／Quality 等診斷功能仍可直達。Ask 保存後會直接承接剛建立的 Proposal，Review 預設優先待處理項目；發布後可直接開啟剛發布的 Wiki knowledge，不需重新篩選。主要列表、窄螢幕操作與詳情面板焦點行為亦已修正。
- **操作診斷**：未預期的 REST 5xx 會在 server log 留下預設可見的診斷；公開錯誤仍只提供安全的固定訊息，記錄不包含 query string、request body 或 headers。
- **MCP 頁碼一致性**：既有 read-only wiki list tool 的預設頁碼改為零起始的 `0`；沒有新增 MCP tool 或寫入能力。

## 支援範圍

### SUPPORTED

- `LOCAL_ONLY` loopback 使用方式與 SQLite／FTS baseline；provider 或 optional backend 未啟用時，基本流程仍可用。
- Inbox 上傳、背景處理、readiness、bounded content preview，以及 grounded stateless Ask；文件範圍 Ask 是既有 Ask 的 additive scope。
- Governed Proposal → Draft → Human Review → explicit Publish 流程；Proposal 核准只準備草稿，不代表知識已發布。
- MCP 僅為本機 loopback read-only adapter，沿用既有 tools 與 auth boundary。
- `PRIVATE_INGRESS` Mode 1 僅在既有 canonical browser origin 等配置完整對齊時為 `SUPPORTED`；細節以目前部署契約為準。

### CANDIDATE／選擇性能力

- Vector／semantic retrieval 需要 pinned `sqlite-vec` `v0.1.9` native extension 與有效 projection。已驗證範圍為 Linux x86_64 CI 及 macOS Apple Silicon local evidence；其他 OS／CPU 不宣稱支援。缺少 prerequisite 時回報 typed unavailable，FTS baseline 不受影響。
- Graph 是 optional derived projection，需明確啟用且 readiness 為 READY；Graph disabled、stale 或 unavailable 時不取代 SQLite authority，也不阻擋 lexical baseline。
- Public HTTPS Mode 2 仍是 `REVERSE_PROXY_CANDIDATE`；raw backend 不可直接對 public network bind。
- Remote provider 使用者須自行配置並依 provider egress disclosure 判讀本次請求的實際呼叫狀態；本候選不保證第三方 provider 可用性或品質。

### NOT SUPPORTED／DEFERRED

- OCR、掃描 PDF 與 layout-aware provider ingestion。
- MCP／agent 寫入、autonomous publish、repair 或 auto-fix。
- Semantic query rewrite、multi-query、HyDE 的 production default adoption。
- Public HTTPS Mode 2 支援宣稱、raw backend public bind，以及未量測的效能／SLA／live-provider quality guarantee。

## 升級與資料遷移

- 使用既有 knowledge root 啟動此版本時，Flyway 會自動套用新的 `V35__single_usable_wiki_draft.sql`；`v0.2.1` 以來其他已發布 migration 不會被修改。
- 同一 workspace／proposal 若有多份舊的 `DRAFT`／`READY`，遷移會保留最新 id 為可用草稿，將較舊列標為 `INVALIDATED`。較舊草稿內容仍留在資料庫供稽核，migration 不會 publish、刪除或改寫 canonical Wiki 頁面。
- 新增 partial unique index，防止 auto-draft 與手動建立在併發時形成多份可用草稿。一般升級不需要手動 SQL 或修改知識檔案。
