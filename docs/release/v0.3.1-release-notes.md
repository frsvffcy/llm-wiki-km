## 支援範圍

### SUPPORTED

v0.3.1 patch candidate 延續 v0.3.0 已發布且已驗證的產品邊界，並只加入本次 corrective：

- upload → READY_TO_USE → grounded Ask / citation。
- Ask 保存成 Proposal → Human Review → Approve → Draft / Preview → explicit Publish。
- Published Wiki read 與既有 workspace-scoped canonical authority。
- 本 patch 新增的 ASK durable evidence currentness 與 publish commit-point fail-closed correctness。
- 真人 Answer Provider failure 的 operator-safe subtype 診斷，以及 grounded-answer prompt/validator invariant 對齊。
- 「知識」→「已發布知識」清單分頁 顯示「共 N 筆」。

### CANDIDATE／選擇性能力

下列能力維持既有候選／選擇性定位，不因 v0.3.1 patch 升格為新的預設承諾：

- semantic / vector retrieval 仍受 capability readiness 與 degradation contract 約束。
- Graph projection / traversal 仍是 derived、provider-neutral projection，不成為 canonical authority。
- 本文件本身描述的是 `0.3.1` CANDIDATE；只有 Release Candidate gate 與 packaged human checkpoint 都通過後，才能判定 READY_TO_PUBLISH。

### NOT SUPPORTED／DEFERRED

本 patch 明確不新增或升格以下能力：

- OCR／掃描型 PDF 自動擷取。
- MCP write／agent write／auto-publish／auto-approve。
- 新 retrieval ranking、query transformation default，或與本次 grounded-answer corrective 無關的 prompt policy。
- 新 provider、Graph authority 或未驗證的 public backend exposure。
- 任何未有獨立 Issue、驗收證據與 publication authorization 的新功能。

## Patch 摘要

v0.3.1 不新增產品功能。相對 v0.3.0，production scope 收斂為 correctness / governance patch 加上一個小型 Browser 顯示修正。

### 1. ASK Proposal durable evidence currentness

Refs #649 #651

Ask 保存成 Proposal 後，後續治理流程不再只相信「當初曾經有效」的 citation：

- ASK evidence 使用 versioned durable snapshot。
- WIKI citation 持久化 validated revision 與 canonical knowledge identity。
- duplicate save 在回傳既有 Proposal 前會重新驗證 evidence。
- REVIEW → APPROVED 前重新驗證 evidence currentness。
- auto/manual/regenerate draft 建立時再次 fail closed。
- legacy / malformed ASK snapshot 不發明 revision，維持 fail-closed。
- SOURCE workspace/status/parse/chunk authority 與 WIKI revision/content authority drift 都有 deterministic integration coverage。

### 2. Publish commit-point TOCTOU corrective

Refs #652 #653

關閉 publish preflight validation 與 canonical commit 之間的 consumption-window race：

- CREATE / MERGE finalizer 在 canonical metadata commit 前使用共用 commit-point guard。
- finalizer transaction 的第一個 DB statement 先取得 SQLite writer serialization，再重讀 fresh draft / proposal / persisted ASK evidence。
- stale evidence 沿用 stable `WIKI_PUBLISH_PROPOSAL_INVALID`，不得默默完成 publish。
- file 已 stage/commit 後才發現 stale 時，沿用 deterministic filesystem compensation / ledger safe-state。
- app-owned Wiki publish 以 persistent per-workspace lock 序列化，不使用不安全的 lock handoff remove lifecycle。
- deterministic concurrency tests 覆蓋 SOURCE/WIKI drift、CREATE/MERGE parity、2-thread attempt barrier 與 3-thread lock handoff；不以 sleep/retry luck 當 correctness evidence。

### 3. Answer Provider 真人相容性 corrective

Refs #658 #659 #660

- 保留 `ANSWER_PROVIDER_INVALID_RESPONSE` 的 operator-safe、redacted、bounded subtype diagnostic；public API message 不洩漏內部細節。
- 真人 exact candidate 已定位實際 subtype 為 `INSUFFICIENT_EVIDENCE_CONFLICT`。
- validator 持續 fail-closed：`insufficientEvidence=true` 時 `citedEvidenceIds` 必須為空。
- production grounded prompt 由 `grounded-answer@v2` 版本化升級為 `grounded-answer@v3`，明確把 sufficient / insufficient 兩個合法 citation 分支傳達給 provider。
- 不放寬 citation authority、不接受矛盾 provider response、不記錄 raw provider response。

### 4. 「知識」→「已發布知識」清單分頁 文案修正

Refs #650 #654

- 「知識」→「已發布知識」清單將 `totalElements` 正確顯示為「共 N 筆」，不再誤標為「共 N 頁」。
- regression fixture 明確使用 `totalElements != totalPages`，並同時鎖定 prev / next button state。
- 不變更 API、page size、filter 或 pagination authority。

### 5. 引用來源定位按鈕版面修正

Refs #662

- 修正「提問 → 引用來源」中「檢視來源位置」按鈕被 CSS Grid auto-placement 壓入 30px 編號欄，造成逐字換行與高度異常。
- locator button 改為 citation 內容欄內的互動元件，既有 sourceChunkId、inline preview、currentness 與唯讀 authority contract 不變。
- Browser regression 鎖定按鈕不得再成為 citation card 的第三個 direct grid child。

## 不變的產品邊界

本 patch 不改變以下既有治理與架構：

- 不自動核准 Proposal。
- 不自動發布 Draft。
- Human Review 與 explicit Publish gate 保持不變。
- 不改 retrieval ranking / query transformation default；本 patch 僅版本化調整 grounded-answer prompt contract。
- 不新增 provider。
- 不改 Graph authority / vector capability policy。
- 不新增 Flyway schema migration。
- v0.3.0 tag / Release / assets 不重建、不覆寫、不 retag。

## Release Candidate 必要驗收

Refs #655

正式給出 `READY_TO_PUBLISH` 前，必須以 exact packaged candidate 完成既有 `.github/workflows/release-candidate.yml`：

- reproducible build twice / bit-identical SHA-256；
- Maven / runtime / manifest / artifact identity 一致；
- clean-install smoke；
- backup → fresh-root restore → restart smoke；
- Browser first-mile packaged gate；
- sqlite-vec JDBC smoke；
- product acceptance；
- readiness gate 明確輸出 `READY_TO_PUBLISH` 或 `NO-GO`，不得 fake-green。

另需 packaged human checkpoint：

- upload → READY_TO_USE；
- grounded Ask + citation；
- 保存成知識 → Review → Approve → draft / preview；
- explicit Publish → Published Wiki read；
- 肉眼確認「知識」→「已發布知識」清單底部分頁資訊顯示「共 N 筆」；
- 不以人工 timing 嘗試重現 concurrency race；該 correctness 以 deterministic executable tests 為 authority。
